# Flipkart E-commerce Decision Intelligence (capstone)

All data is synthetic (produced by `generate_data.py`); nothing here reflects real Flipkart records or performance. Every number below is copied from the committed files in `outputs/`, which are regenerated by the scripts. Money is in Indian Rupees (INR).

## How to run

From a clean clone, in this order (Python 3.10 or newer):

```
pip install -r requirements.txt
python generate_data.py
python part1.py
python part2.py
python part3.py
python part4.py
python -m unittest discover tests
```

`generate_data.py` must print `800 10 170 c6f249ba693f1ebeed318d6d5e18de23`. `common.py` holds the helpers shared by the Parts (importing it runs nothing). `data/records.csv` is marked `-text` in `.gitattributes` because its checksum depends on its original line endings. Each script writes its files into `outputs/`.

## Part 1 findings

- **R1.1** H0 (mean order value = 8.0, i.e. INR 800) is rejected: `z_stat` = 2.8930, which exceeds the critical value 1.96 (`reject_h0` = yes). A Type I error here would mean concluding that the true average order value differs from INR 800 when in fact it is INR 800, and re-planning the category budgets for nothing. The gap `mean_value` - 8.0 = 8.9382 - 8.0 = 0.9382 column units (about INR 94). That is about 12% of the planned value; it is statistically clear, and for a category plan it is probably worth adjusting, but its practical weight should be judged against margin and volume, not against the p-value alone. The 95% interval is 8.3026 to 9.5738.
- **R1.2** `n_required` = 1293 records to reach a margin of 0.5 units (INR 50), against 800 rows available. The current sample is too small for that precision: our margin is about 1.96 x 0.3243 = 0.64 units, so the team needs roughly 500 more records (or a looser margin) if it wants the INR 50 target.
- **R1.3** `gd_slope_gap` = 0.0000 (below 0.001). The cost is a convex bowl with a single minimum, and with a sensible step size (0.1 on a standardised predictor) 500 full-batch updates walk to the same point as the closed-form solution (`gd_J100` and `gd_J500` are both 40.3698).
- **R1.4** `resid_sd_ratio_raw` = 3.7525 and `resid_sd_ratio_log` = 1.0396. The raw model shows a strong funnel (residual spread in the upper half of fitted values is 3.75 times the lower half), and the log-log model removes it (ratio close to 1).
- **R1.5** Predictors in Task 1.7 with an absolute coefficient above 0.05: ln(X4) (1.1576), X2 complaint count (0.0940), X3 discount share (0.1067) and X6 cod flag (0.1518). This is a mechanical threshold on coefficients in different units, not a ranking of importance. `mr_adj_r2` = 0.7403 versus `loglog_adj_r2` = 0.6561, so the extra predictors earn their place (adjusted R2 rises by about 0.08 even after the penalty for seven predictors).

## Part 2 findings

- **R2.1** After 200 updates the losses are, from lowest to highest, eta 1.0 (0.3703), eta 0.1 (0.3776), eta 0.01 (0.5091): a learning rate that is too small has barely moved the model after 200 updates, while the large rate was still stable on this smooth, standardised problem and converged fastest (it would not necessarily be safe on other data).
- **R2.2** The largest absolute weights are X3 discount_order_share (0.9013), X1 customer_tenure_months (-0.5554) and X2 complaint_count_90d (0.5505). The largest odds ratio is 2.4629 for X3: for one training SD more discount-order share, the odds that a customer churns are multiplied by about 2.5, other things equal.
- **R2.3** `blind_accuracy` = 0.7875 versus 0.8042 for the model at tau = 0.5: predicting "nobody churns" is almost as accurate, because only 51 of 240 test records are positive, so accuracy rewards ignoring the customers we care about. Lowering tau from 0.5 to 0.3 raised recall from 0.4706 to 0.7451 and lowered precision from 0.5455 to 0.4634.
- **R2.4** At tau = 0.3 the logistic model has f1 = 0.5714 and recall = 0.7451; KNN (K = 5) has f1 = 0.3696 and recall = 0.3333. Logistic regression is clearly better on both.
- **R2.5** Deploy the logistic model at tau = 0.15 (`cost_tau`). Test cost at that threshold is INR 6050 (`cost_test_at_tau`), against INR 11800 at tau = 0.5 (`cost_test_at_0.5`) and INR 20400 if nobody is flagged (`cost_test_flag_nobody`). The threshold was chosen on training rows because test rows must stay untouched to give an honest estimate of how the choice performs on new customers.

## Part 3 findings

- **R3.1** WCSS runs 2262.6753 (K = 2), 1602.8471, 1494.7732, 1323.7157, 1278.1691 (K = 6). The WCSS drops are: WCSS(2) - WCSS(3) = 659.8282, WCSS(3) - WCSS(4) = 108.0739, WCSS(4) - WCSS(5) = 171.0575, WCSS(5) - WCSS(6) = 45.5466. `elbow_k` = 3: the drop from 3 to 4 (108.0739) is below half of the drop from 2 to 3. The drops do not shrink steadily (the 4 to 5 drop is larger than the 3 to 4 drop) because the pinned starting rows give one reproducible solution, not necessarily the global optimum. K = 3 is used throughout.
- **R3.2** Segments (from `part3_segments.csv`):
  - **A, "premium loyal" (322 customers):** tenure 47.5 months, discount share 0.2250, loyalty score 62.1584, outcome rate 0.0186. Action: protect with early access and loyalty perks; no retention coupon.
  - **B, "high-spend, complaint-prone" (255 customers):** 6.0706 complaints, average past order 28.7192 hundreds, mean order value 17.1248 hundreds, outcome rate 0.2353. Action: proactive service recovery and a dedicated complaint follow-up.
  - **C, "bargain-focused newcomers" (223 customers):** tenure 14.3892 months, discount share 0.7118, loyalty score 38.5215. Action: targeted coupons and onboarding offers to build loyalty.
  - Segment C has the highest `outcome_rate`, 0.4664.
- **R3.3** Single linkage cut gives 4 clusters: {E1}, {E4}, {E5}, {E2, E3, E6}. Complete linkage cut gives 2 clusters: {E1, E4, E5} and {E2, E3, E6}. Single linkage joins clusters by their closest pair, so chains of near neighbours merge at low heights and the biggest gap appears early (between merges 2 and 3); complete linkage uses the farthest pair, so the two cohort groups stay apart until the very last merge at height 7.9000, which creates one dominant gap. (Average linkage also gives 2 clusters.)
- **R3.4** PC1 contrasts tenure (+0.5317) and loyalty score (+0.4418) against discount share (-0.5187), complaints (-0.4100) and average order value (-0.2916): a "loyal and long-tenured versus discount-seeking and complaining" axis. The mean vector of the standardised data is all zeros (step 1). Three components are needed for at least 80% of the variance (`cumulative_ratio_2` = 0.7593, `cumulative_ratio_3` = 0.8616). `mean_pc1_segment_A/B/C` = 1.7773, -0.7831, -1.6709, so PC1 orders the segments from loyal (A) through middle (B) to discount-driven (C).

## Part 4 findings

- **R4.1** S4 (tenure <= 24 months) is the best split by both information gain (0.1252) and Gini gain (0.0606) because it separates the churn rate most sharply (0.4574 of the yes side versus 0.0887 of the no side) while keeping both sides large. A tree grown until every leaf is pure would memorise noise and individual customers, so it would overfit and do worse on new records. A maximum depth, or a minimum number of records per leaf, stops a tree growing too deep.
- **R4.2** I would ship the logistic model: f1 = 0.5714, recall = 0.7451. The stump gets f1 = 0.5532, recall = 0.7647; hard vote f1 = 0.5344, recall = 0.6863; soft vote f1 = 0.5507, recall = 0.7451; KNN f1 = 0.3696, recall = 0.3333. Combining did not help: neither vote beat the logistic model on f1.
- **R4.3** After round 1 normalisation the two misclassified points (3 and 7) carry a total weight of 0.5000 (0.2500 each). Round 2 trusts h2 more because under those weights h2 errs on weight 0.1667 (`round2_error`) whereas h1 would err on weight 0.5000, so `round2_alpha` = 0.8047 exceeds `round1_alpha` = 0.5493. Ensemble accuracy on the eight points is 0.7500.

For 10 classes I would use ReLU in hidden layers and softmax at the output with categorical cross-entropy loss. In a very deep plain network the gradient is a product of many small factors on its way back, so early layers receive almost no signal and stop learning; a skip connection adds the input to a layer's output, giving the gradient a direct path back to early layers. (The out-of-bag fraction for a 560-row bootstrap is `oob_fraction` = 0.3676.)

## Model-choice memo

To: Head of the Retention Team

I recommend the logistic-regression model. On the 240 test customers at tau = 0.3 it gives f1 = 0.5714 and recall = 0.7451, ahead of KNN (f1 = 0.3696), the stump (0.5532) and both votes (0.5344 hard, 0.5507 soft); combining models added nothing.

Threshold: send a retention coupon to customers with churn probability of at least 0.15. This threshold was chosen on training rows by minimising cost at INR 50 per false alarm and INR 400 per missed churner. On the untouched test rows it costs INR 6050, against INR 11800 at the default 0.5 and INR 20400 if nobody is flagged. These figures are for the logistic-regression model; I did not compute the cost rule for the other models.

Why trust it: the strongest drivers are discount share (odds ratio 2.4629), short tenure and complaints, which matches the segments, where bargain-focused newcomers churn at 0.4664.

Risk: the test set holds only 51 churners and the data is a single synthetic split, so the INR 6050 estimate could move noticeably with a different split; monitor real outcomes before relying on it.

Model A (product pictures) or Model B (review text): neither is worth building before the structured model is in production, since the structured model already answers the retention question.

## Limitations

- The data is synthetic and generated from a known recipe, so results say nothing about real Flipkart customers, and the model may look better than it would on messy real data.
- One fixed 560/240 split is used throughout; the best K, the threshold of 0.15 and all test costs are valid for this split only, and the test set has just 51 positive records, so rates such as recall carry wide uncertainty.
- Part 3 uses pinned starting rows, so K-means gives one reproducible local solution, not necessarily the global optimum; the hierarchical clustering uses a supplied six-cohort table, not our own records.
- The cost figures (INR 50 and INR 400) are rough planning assumptions, and the threshold is chosen from training-row probabilities, which are slightly optimistic compared with unseen rows.
- Models A and B are only sized (parameter counts), never trained, so nothing here shows they would perform well.
